# Operating guide

## One complete run

After installation and raw-data placement, run:

```powershell
.\scripts\run_experiment.ps1 -Stage all -Epochs 50
```

The stages execute in this order:

1. `check-data` verifies paths, the `id` column, source OBJ/CSV presence, and mutually exclusive split IDs.
2. `prepare` validates ordered OBJ/CSV surface correspondence, reduces each mesh, creates PhysicsNeMo graph features, and writes `artifacts/simjeb_physicsnemo_mgn_v1/prepared_graphs/`.
3. `train` fits the model on train designs and writes `models/meshgraphnet.pt` and `models/history.csv`.
4. `evaluate --split validation` writes validation predictions and metrics.
5. `evaluate --split test` writes final test predictions and metrics for the app.

Raw OBJ and CSV files are never overwritten.

## Expected time and storage

For the 378-design supplied split on an idle 4 GB RTX 3050 Laptop GPU, reserve roughly 1.5–2.5 hours for 50 epochs with per-epoch validation. The first `prepare` step is CPU-dominated; reserve 3–5 hours for the complete first run. This varies with OBJ size, disk speed, driver, laptop power mode, and other GPU use. A 100-epoch run is roughly twice the training time.

Keep the laptop connected to power and use a high-performance GPU mode. The original 2,048-face FP32 setting was chosen because larger graphs are less reliable in 4 GB VRAM.

## Review results

Start the local app only after final test evaluation:

```powershell
.\scripts\open_results_app.ps1
```

Open `http://127.0.0.1:8054`. Select a test design, load case, and field. The page shows actual, predicted, and absolute-error meshes; an actual-versus-predicted scatter; per-case metrics; and the saved train/validation curve.

## Files generated by a successful run

```text
artifacts/simjeb_physicsnemo_mgn_v1/
├── data_contract.json
├── prepare_manifest.csv
├── prepared_graphs/<case_id>.npz
├── models/meshgraphnet.pt
├── models/history.csv
├── metrics/meshgraphnet_validation.csv
├── metrics/meshgraphnet_test.csv
└── predictions/{validation,test}/<case_id>_<load>.npz
```

## Safe reruns

`prepare` reuses an existing graph file by design. Delete only the specific experiment directory under `artifacts/` when you intentionally want to rebuild generated graphs after a data or configuration change. Do not delete raw data.

Running `train` replaces the saved checkpoint and history for that experiment namespace. Copy or rename `artifact_namespace` in `configs/experiment.yaml` before a new experiment if you want to preserve a previous run. Do not use the test split to pick epochs or settings; use validation for that decision.

## Small smoke test

Before a full run, use a new temporary artifact namespace and a small, purpose-made split that has at least one design in each split. `--limit` only limits preparation and therefore should not be used with the supplied full split for training. A proper smoke test must use a matching small split file.
